## 결정과 이유

- **AI 는 「프롬프트 생성 + 답변 붙여넣기」 방식(기획서 7장 방식 2)으로 했습니다.** 기획서 10장에서 호출 방식이 미정이지만, 키·비용 부담이 없고 정적 페이지에 키를 두지 않아도 되는 쪽을 1단계 기본으로 골랐습니다. 출제·평가·모범답안 세 곳 모두 같은 방식입니다.
- **AI 답변은 대괄호 머리줄로 나눕니다.** 출제는 `[번호] 영역명` 다음 줄에 문제, 평가는 `[가스기술사] 점수: 70` 다음 줄에 의견, 마지막에 `[종합의견]`. 프롬프트에 이 형식을 적어 두었고, 굵게(`**`)·`문제:` 같은 흔한 변형과 번호 대신 영역명을 쓴 경우도 읽습니다. 나눈 결과는 저장 전에 칸으로 보여 주어 고칠 수 있게 했습니다.
- **풀이 순서를 고정했습니다.** 제출 전에는 평가 프롬프트가, 평가 저장 전에는 모범답안이 열리지 않습니다. 원문 흐름 「[문제] → [사용자 답안 작성] → [AI 평가] → [모범답안 공개]」를 지키고, 모범답안을 먼저 보고 답안을 쓰는 일을 막기 위함입니다. 답안은 제출하면 고정되고(평가 대상이 바뀌지 않게), 평가 전까지만 제출을 취소할 수 있습니다. 답안이 생긴 문제는 문제 문장도 고칠 수 없습니다.
- **출제 이력 참조**: 출제 프롬프트에 영역마다 최근 20문제를 넣어 겹치지 않게 요청하고, 저장할 때도 이전 문제와 글자 2개 묶음 기준 80% 이상 비슷하면 경고합니다(막지는 않음). 기준값은 `config.js` 에 있습니다.
- **사실 오류 방지**: 평가·모범답안 프롬프트에 「법령·KGS 조항 번호, 사고 날짜·장소·피해 규모는 확실할 때만 쓰고 아니면 `[확인 필요]`」를 넣었고, 모범답안에 그 표시가 있으면 개수를 경고합니다(기획서 10장 「사실 정확성」).
- **카드는 「출처 있음 + 원문 확인 체크」여야 「출처 확인」 배지**를 답니다. 출처 칸이 비었거나 확인 체크가 없으면 「미확인」. 기획서 10장의 「1차 출처가 확인된 자료만」 원칙을 화면에서 구분할 수 있게 한 것입니다. 출처 없이 확인 체크만 하면 저장을 막습니다.
- **예시 데이터에 기술 사실을 넣지 않았습니다.** 문제는 교재에 흔한 일반 주제를 「(예시)」를 붙여 문제 형태로만 적었고, 답안·평가·모범답안 칸은 자리표시 문구입니다. 사고·기술 카드도 양식 확인용 빈 카드 1장씩입니다. 지어낸 사고 정보나 기술 설명이 공부 자료처럼 남지 않게 하기 위함입니다. 점수는 현황표·그래프를 보여 주는 임의의 값입니다.
- **엑셀 머리행은 한글 이름**(날짜·영역번호·문제·가스기술사 점수…)으로 썼습니다. 제출자가 엑셀에서 바로 읽기 쉽게 하려는 것이고, 가져오기는 한글 이름과 필드 키(set_date 등) 둘 다 받습니다.
- **스크립트를 ES module 이 아닌 일반 스크립트로** 불러옵니다. `index.html` 을 파일로 열면(file://) 브라우저가 module 스크립트를 막아 화면이 통째로 비기 때문입니다(data09-01 과 같은 방식). `logic.js` 는 Node 테스트에서도 같은 파일을 불러 씁니다.

- **붙여넣은 기사는 엑셀 백업에 넣지 않음** — 기존 3시트 구조와 가져오기 검증을 바꾸지 않기 위해. 대신 CSV 내보내기와 사고 카드 등록(엑셀에 들어감)을 둠.
